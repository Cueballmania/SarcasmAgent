Explore HVE Core's RPI workflow ↗
Allow about one minute. RPI names Research, Plan and Implement. HVE Core's coordinated workflow also includes Review and Follow-up, so show the complete loop rather than treating implementation as the finish line. Research establishes the facts, Plan bounds the change, Implement builds and validates it, Review compares the result with the plan, and Follow-up selects required remaining work. Evidence from running and evaluating the app can start the next scoped RPI cycle. Follow-ups need not repeat investigation when existing evidence is adequate. The visible link opens the official RPI skill contract. RPI Agent is an optional coordinator; the phase skills also work standalone. Manual and automatic progression have explicit boundaries, and neither removes required approvals.

Langfuse connects the evidence to the next RPI cycle.

Allow about one minute. The core point is that observability and evaluations are essential parts of maintaining the app, not an optional final polish. Observability explains a request's execution; reviewed evaluations check whether its outcome was correct. A valid response can still be wrong, and an Unknown-rate trend is not a ground-truth accuracy score. Langfuse provides shared traces and linked scores so the evidence can guide another scoped RPI change. Our implementation exports runtime scores, per-case evaluation scores and explicit run summaries; detailed matrices and slices still live in JSON reports. No real accuracy results or preconfigured dashboards are claimed here. Keep audience text out of exported telemetry, and separate runtime and evaluation traffic. The hosted app and a future hosted evaluator run outside Langfuse; the current CI does not make live model calls.
